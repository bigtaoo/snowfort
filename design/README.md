# 雪堡大战 Snow Fort Showdown — 设计

同屏双人对战小游戏，参加 Playgama 挑战赛 **Player Two Found**（2026-10-22 – 11-04，
截止 11-04 18:00 PT，https://playgama.ai/play/challenge/playertwofound/）。
资格线：sandbox 游玩 > 100 次、平均时长 ≥ 5:00；达标者中点赞最多的获胜。必须通过 Playgama MCP 发布。

## 一句话

两个小孩在雪地里各堆一座雪堡，用投石器互扔雪球，把对方的雪人国王打倒。

## 定下的决定（2026-10-26）

- 题材：雪堡。不暴力、贴"天冷了在家"的主题。
- 双人只有**轮流开火**（2026-10-27 去掉了双人同时开火）；对电脑仍是同时开火。
- 建造：**自由搭建**。
- 技术：**3D 渲染（Three.js）+ 平面物理（Rapier 3D 锁住侧翻，前后位置每步手动归零）**。
  不能同时锁前后移动和侧翻：Rapier 0.21 那样会完全没有摩擦，积木和国王像在冰上滑（早期"国王被打没了"就是这个）。
  胜负已定后的回放解锁物理，城堡往各方向塌，镜头绕拍、慢镜头。
- 横屏。主场是电脑键盘；触屏（平板、手机横屏）也要能玩。竖着拿的手机看到半透明的"请横屏"页：
  游戏标题、一部来回转 90° 的手机图标和提示文字，背后透出雪景（菜单等 HUD 这时隐藏）。
- 新仓库，不碰 Holy Kicker（`D:\standing`）的代码和门槛；平台接入从那边复制。

## 一场的流程

1. **搭建**：每人一份预算（雪块、冰块、木板）+ 一个雪人国王，只能放在自家场地。物理全程开着，搭不稳当场塌。
   - 电脑（一个鼠标）：轮流搭，每人 2 分钟，鼠标拖放，搭好可提前点 Done。对方城堡看得见，可以针对着搭。
   - 触屏：两人同时在各自半边搭（多点触控），限时 2 分钟，两人都点 Done 就提前开打。
   - 放下的块可以再拿起来挪位置，拖回自己的托盘就退回预算。
   - 和电脑对战：搭建和局间修补都不限时，搭好了点 Done 才开打。
   - 可存蓝图，下一场一键"用上次的城堡"。
2. **对战**（双人轮流开火，对电脑同时开火）：每人一个键。炮管角度自动上下摆 → 第一次按锁定角度 → 按住蓄力 → 松开发射。
   键盘 P1 空格、P2 回车；触屏左右半屏。每发后 2–3 秒装弹冷却，准比快重要。
3. **一局的胜负**：国王掉下自家平台、被推出自家院子（越过投石车、出了画面，x 超过 ±12.6），或累计受到的冲击（物理冲量）超过阈值。
   国王头顶有跟着走的小血条，挨打时冒 "-N"（大伤害字更大）、血条闪红，最后一下显示 KO!（只显示一次）。一局最长约 90 秒，
   超时后暴风雪，炮弹越来越重。
4. **局间**：每人 2 分钟（和开局搭建一样，点 Done 提前结束）+ 几块材料修补城堡，再三选一一张卡（输家先选）：
   - 城堡类：冰墙、国王屋顶、诱饵国王、弹簧围栏；
   - 弹药类：大冰块（重、穿透）、分裂雪球、冰冻雪球（落在对方平台上冻住对方投石车 3 秒）、热可可（融冰）、烟花（直线快）；
   - 规则类：下局大风（对方的球受 4 m/s² 逆风，原来 9 太强，高抛球会被吹回十几米）、对方装弹慢 30%、我方首发三连。
   - 选卡 12 秒，最后 6 秒显示倒计时，超时随机选。弹簧围栏再拿一张就换新的，不叠在一起。
   - 弹簧围栏：悬崖边和建造区之间那条地上立一块绿色弹板，很重、血量 5 倍，平射的球会被弹回去，约挡 5 发；弹回时"啵嘤"一声。
   - 烟花：装着烟花时炮管改在 −4°–24° 之间摆，直接对着国王平射。原来和普通球一样最低 12°，又是从高处发射，
     最平的一发也从国王头顶约 2 米飞过去，谁都打不中国王；现在会打在城堡正面国王高度、一点点凿穿，弹簧围栏正好克它。
5. 先赢 3 局获胜，一场约 6–10 分钟。
6. **胜利回放**：最后一发慢镜头，镜头跟球、绕着倒塌的城堡转半圈。可截图，是分享和封面素材。

## 玩法原型（`game/`，2026-10-26）

- 运行：根目录或 `game/` 下 `npm run dev`。所有可调数值只在 `game/src/config.ts`。
- 画面已接上 lookdev 的外观（`game/src/look/`）：toon 积木按块微调亮度、受伤变粉，雪人国王、小孩、投石车（臂随角度转、装好弹时球在勺里）、
  雪球命中扬雪，院子背景和回放都用同一套。
- 镜头：横向只看到 ±12.8、底边钉在 y −1.2，镜头略高往下看（天空少、院子多）。场地整体压紧：峡谷 ±1.5、
  建造区 1.85–8.7（悬崖和建造区之间留一条放弹簧围栏）（在投石车前约 2 格截止，雪球不会从自家城堡里射出）、最高 9，投石车在 ±10.8，小孩站在投石车前侧。16:9 下城堡和地面约占下半屏；
  5:4、4:3 受宽度限制，约占四成（要看到两边投石车，没法再大）。手机横屏（高度 ≤ 520 px）由高度决定取景，
  HUD 和工具栏缩到 2/3。
- 搭建阶段屏幕底部给卡牌栏单独留一条：镜头把整个场地往上推到卡牌栏上方；卡牌栏收起（开打）后镜头缓回去，
  露出城堡前面的地面。
  嵌在门户页里时，页面可能把游戏框排得比屏幕还高（Playgama 上见过卡牌栏只露出一半）：游戏用 IntersectionObserver
  看框里实际露出的那一段，把整个 HUD 缩进这一段（上下各最多让出框高的 40%），镜头跟着卡牌栏一起上移。
  松树都退到篱笆后面远处（z −15 以外），画面先看到城堡。
  两座平台中间是峡谷（宽 5、深 7），平台前沿 z 5 是悬崖，悬崖下是低一层的雪地和一条冰河；崖壁上浅下深、沿边一圈雪檐。
- 回放绕拍从峡谷那一侧绕过去，投石车和小孩不挡城堡。
- 模式：
  - 双人轮流开火：电脑上轮流搭建，触屏上同时搭建。（双人同时开火 2026-10-27 去掉了。）
  - 对电脑（2026-10-27 改版，起因：77 个玩家里大多数没扔出第一发就走了，打完三局的只有个位数）：
    - 菜单只有两个按钮：双人轮流、对战霜霜。不再让玩家选难度。
    - 一场只打一局。双方都用预设城堡，直接开打：第一场玩家的城堡随机给一座预设；从第二场起先给 30 秒调整
      （放上玩家上次的城堡，没有就随机预设，可以点 Done 提前开打）。电脑的城堡每场随机一座预设，边打边落下来。
    - 双方国王同时倒下（平局）就用开局时的两座城堡原样重打，不算输赢。没有局间修补，也没有选卡。
    - 打完是结算面板：标题 + 「下一局（5）」倒数，5 秒后自动开下一场；也可以点「菜单」取消。
    - 难度 1–100 级：赢一场升一级，输一场降一级（最低 1、最高 100）。存在 `snowfort.cpu`
      （`{level, played, streak}`，旧存档没有 streak 就从 0 算），存不了就每次从 1 级开始。
      2026-10-29 起等级不再隐藏：对局中霜霜名牌写"霜霜 Lv.N"，结算面板写"霜霜升到了 Lv.N！"/"降到了 Lv.N"，
      连胜 2 场以上再写"N 连胜！"，给玩家一个继续打的目标。
      各项能力从 1 级（`CPU.weakest`）到 100 级（`CPU.strongest`）直线过渡：角度噪声 9°→1°、力度噪声 3→0.3、
      思考 4 秒→0.3 秒、被诱饵骗到 90%→15%；故意大幅打偏的投掷（`wildShot`）从 75% 到 60 级（`wildFadeAt`）降到 0。
  - 电脑对手有名字，不叫"电脑"：中文"霜霜"，英文等拉丁文字 Frosty，日 / 韩 / 俄 / 泰按音译；菜单、名字牌、提示和结算都用这个名字。
    瞄准：按所选角度二分求速度，算上重力和逆风；烟花太快落不到国王身上，改成随机挑速度、二分求一条穿过国王的角度。
    以前的"按落点修正"去掉了：它把撞墙当成"打近了"，越修越远，导致简单档反而赢中档，强逆风下双方几百秒打不中。
- 搭建：
  - 预算 12 雪、5 冰、4 木板（横竖共用）、1 国王。
  - 有"随机城堡"和"用上次的城堡"两个按钮。
- 伤害：
  - 每步接触冲量扣掉材料护甲，剩下的算伤害。
  - 雪球直接打中算全额；块撞块、块撞地只算 30%。
  - 积木在承受范围内会倒塌，超过就碎成碎块。
  - 国王单次受伤最多扣 60% 血，任何弹药都至少要两发。
    "一次"按时间窗算：第一下接触后 0.8 秒内的伤害（球连续几帧的接触、被它砸过来的积木）合成一次。
    以前按物理步算，一发就能打晕。
  - 每局开头 1.2 秒内不算伤害，让卡牌放下的块先落稳；搭建阶段也不算。
- 局间补修：5 雪、2 冰、1 木板。国王如果被推出了自家建造区，局间收回托盘，要重新放（电脑和自动摆放会自己放回）。
- 上一发弹道：每边最近一发的轨迹用自己颜色的淡点画出来（到第一次碰到东西为止），下一发好修正；新的一局清空。
- 屏幕震动：大冰块落地、国王挨重击时镜头抖一下，伤害越大抖得越厉害。
- 音效：全部用 WebAudio 现场合成，没有音频文件。
  - 有锁定、发射、各弹药命中、雪/冰/木碎裂、国王挨打、KO、开局铃、赢一局、赢全场、按钮、放置这些声音。
  - 同一种声音 45 ms 内不重复。回放时跟着慢镜头降调。
  - 第一次按键或触摸后才出声，页面切走时静音。
  - 右上角有静音按钮，状态存在 localStorage。
- 瞄准点和蓄力条都加大了：
  - 瞄准点是白边彩心，共 7 个。
  - 蓄力条竖在小孩头顶，有深色底槽。
  - 两者都画在城堡前面，不会被挡住。
- 轮流模式：
  - 球落地 0.5 秒后就换人，最多等 3.2 秒。
  - 所有伤害 ×1.4，每发更有分量。
- 实测（自动对局，两边都是电脑，2026-10-27）：
  - 同时开火（现在只有对电脑）：一局约 10–70 秒，一场打斗时间约 1.5–2.5 分钟。
  - 轮流：一发约 3.7 秒，一局约 10–60 秒，一场打斗时间约 1–3 分钟（改之前 3–4 分钟）。
  - 几乎都是被打晕；掉下平台、推出院子很少见（摩擦修好以后）。
  - 加了新卡以后（2026-10-27，强制一方拿弹簧围栏、另一方拿大冰块或冰冻雪球）：没有报错，冰冻每场触发 0–9 次。
    约 30 局里有 1 局是一块大冰块直接把靠后站的国王推出院子，暂时接受。
  - 双方乱射约 46 秒磨掉六成城堡；瞄准国王要 3–4 发好球。
  - 电脑各档对打（2026-10-27，改成 100 级以前的易/中/难，每组 4 场）：中胜易 9:6，难胜中 9:4，难胜易 12:1；一场打斗约 70–80 秒。
    改了烟花以后复测（每组 3 场）：中胜易 9:3，难胜中 7:5；轮流模式中对中一场打斗约 100 秒。
  - 自动对局工具：`game/src/dev/selfplay.ts`（游戏不引用它），开发服务器控制台里 import 后 `run([[10, 60]], 4)`（两边的等级），
    看 `summary()`。它不改玩家的等级记录。
- 已知问题：
  - 加上搭建、修补、选卡，一场两人对战约 5–7 分钟；比赛要求平均 ≥ 5 分钟，正好够。

## 新手引导（2026-10-27）

- 没有单独的教学关，第一次遇到每一步时，在要操作的地方冒一个带箭头的提示气泡（`game/src/coach.ts`），
  做到了就消失，并记在 localStorage `snowfort.coach` 里，以后不再出现。URL 加 `?tips` 从头再看一遍（会重写记录）。
- 顺序：
  1. 菜单：「对战霜霜」按钮发光，标着 NEW? START HERE；开始任意一场就算学会。
  2. 搭建（对电脑的第一场不搭建，从双人或对电脑的第二场起才看到）：指着雪块按钮"把一块拖到你的院子里" → 指着国王按钮"放上雪人国王" → 指着 Done"城堡好了就点 Done"。
     点"随机城堡 / 上次的城堡"也算学会了拖和放国王。两人同时搭建时两边托盘各指一个。
  3. 局间修补：指着 Done"用几块备用材料补洞"。
  4. 对战（第一局）：每个真人玩家的投石车上方，按键盘 / 触屏分别写"按空格（回车）/ 按住左（右）半屏，锁定摆动的瞄准"，
     锁定后变成"按住蓄力，松开发射"；这一方扔出第一发就消失。所有真人都扔过以后才算学会，两人对战两个人都会看到。
  5. 第一发扔出后，指着对方国王 6 秒："打倒对方国王！把血条打空或推下山 · 先赢 3 局"（对电脑时去掉"先赢 3 局"）。只出现一次。
  6. 选卡：卡牌下方"选一张，下一局归你用"。
- 气泡不接收点击 / 触摸，不挡操作；矮屏手机字号缩小（不用 zoom，否则定位会偏）。

## 数据分析（2026-10-27）

- 不用自己的服务器：Holy Kicker 实测 Playgama sandbox（Bridge 平台 `playgama_sandbox`）只放行 Playgama 自己的域名
  （见 `D:\standing\docs\retention.md`）。改用 Bridge 自带的 `bridge.analytics.send`，事件进 Playgama 自己的 telemetry，
  在开发者后台看漏斗。Bridge 自己已经统计会话、时长和广告，不重复发。只在 Playgama 版本里发，开发时是空操作。
- 每个事件都带：`step_id`（对局模式：`turns` / `cpu`；改版前对电脑是 `cpu_easy` / `cpu_normal` / `cpu_hard`）、`mode`、`touch`（触屏还是键盘）、
  `match_index`（本次打开的第几场）、`new_player`（引导还没全部学完）；对电脑时再加 `cpu_level`（这一场的隐藏等级）
  和 `cpu_match`（这个玩家累计第几场对电脑）。
- 对局：
  - `progression_started`：一场开始。
  - `progression_completed`：打完一场，加 `duration_sec`、`rounds`、`score`（如 `3-1`，红-蓝）、`winner`（`red` / `blue`），
    对 CPU 时再加 `won`。
  - `progression_failed`：中途回菜单，`reason: left`，同样带时长、局数和比分。
- 引导漏斗：每学会一步发 `tutorial_step`（`step_id` 为这一步，`step_index` 按 menu、drag、king、done、aim、charge、goal、card、repair
  记 1–9，`seconds` 为打开页面后的秒数），九步全学会再发一次 `tutorial_completed`。数每一步的人数，就能看出新玩家卡在哪一步。
- 菜单前一步（2026-10-28 加，因为加载完的人约一半没开始对局，而对局事件看不到这批人）：加载完发一次 `menu_shown`
  （`touch`、`portrait`：是不是竖着拿的触屏、被"请横屏"挡住）；竖屏提示出现时发 `rotate_prompt`（`state: shown`），
  玩家转成横屏后再发一次（`state: turned`，`seconds` 为打开页面后的秒数）。每次打开页面每种最多一次。
  2026-10-29 起 `menu_shown` 多一个 `straight_in`：新玩家（没学过 menu 这一步）不进菜单、直接开一场对霜霜（竖着拿的手机等转成横屏再开），
  打完结果页上有"菜单"按钮；老玩家照常进菜单。
- 点赞提示：结果页在打赢霜霜或打完一场双人对局时，加一行"喜欢吗？点游戏下方的 ♥ 👇"，每个玩家最多两次
  （存档 `snowfort.likeAsks`），只在 Playgama 上出现；出现时发 `like_prompt`（`ask` 第几次、`mode`）。
  挑战按点赞排名，2026-10-29 时点赞率约 5%，第一名约 10%。
- 插屏广告的 `failed` 多数是 180 秒冷却：连着打的玩家两场之间常在冷却内，Bridge 立刻判失败，游戏照常开下一场，不算问题。
- 报错：某一帧抛异常时主循环照常往下走（下一帧先排上），只在控制台打一次 `[snowfort] frame failed` 并发一次
  `frame_error`（`message` 截到 200 字、`phase`），线上卡死时能从这里看出原因。

## 多语言（2026-10-27，仿 standing）

- `game/src/i18n/`：`en.ts` 是源表，其余表类型为 `Table<typeof en>`，少键或多键都过不了类型检查；`t('a.b', { name })` 取文案并替换 `{name}`。
- 15 种：en、zh 打进主包；de、fr、es、it、pt、pl、ru、ja、ko、vi、tr、th、id 由 `more.ts` 按需加载。
- 选语言顺序：玩家在菜单左上角下拉框选过的（localStorage `snowfort.lang`）→ Bridge `platform.language` → 浏览器语言 → 英语。

## 外观（lookdev 已定，见 `lookdev/README.md` 和 `lookdev/shots/`）

- 卡通平涂：三阶色带 toon 材质 + 反向外壳粗描边，不做 tone mapping；一个太阳硬阴影 + 天蓝半球光。
- 三种积木一眼可分：雪（白、哑光、圆角大）、冰（青色半透 + 高光点，描边用模板缓冲只画在冰外面）、木（暖棕薄长板）。
- 侧视镜头（fov 30）；降雪只在游戏平面后方，不挡战场。院子背景：篱笆、松树、雪堆，反方向有房子，给回放镜头看。
- 人物：两个小孩一暖一冷（暖色在左），雪人国王戴王冠；投石车程序化，臂会转。目前全是基本体拼的
  （每个模型 2 个 draw call），没有 GLB。
- 显存：几何体按形状共用缓存；雪人王每边只建一次，之后都是共用几何体的克隆（回放会重建所有网格）。
  积木和碎块各有自己的材质（受伤变红），实体移除时释放；共用的材质不释放。
- 回放：时间放慢到 0.3 倍约 5 秒，镜头 7 秒内绕城堡半圈并拉近。
- 预算：整场约 40 个 draw call、约 19 万三角形（含阴影），核显上每帧 2 ms 以内。
